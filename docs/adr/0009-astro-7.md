# ADR-0009: Astro 7 instead of Astro 5 (amends ADR-0001)

Status: accepted by the owner, 2026-10-14 (option 1).

## Context

ADR-0001 chose Astro 5 for the static site. During the Phase 0 bootstrap (2026-10-14) the latest 5.x release is 5.18.2, published 2026-05-26; the 5.x line has received no fixes since. `pnpm audit` reports advisories against it that are fixed only in Astro 6 or 7:

| Severity | Package | Advisory | Fixed in |
|---|---|---|---|
| critical | astro | Remote code execution through AVIF image optimization | 7.2.8 |
| high | astro | Host header SSRF in prerendered error page fetch | 6.4.6 |
| high | astro | Reflected XSS via unescaped slot name | 6.3.3 |
| high (3) | sharp 0.34.5 (Astro's optional image dependency) | libvips, libheif and librsvg vulnerabilities | 0.35.0 to 0.35.5 |
| moderate (5), low (3) | astro, esbuild | XSS variants in spread attributes, view transitions, define:vars; dev server file read on Windows | 6.x to 7.1 |

The CI gate `pnpm audit --audit-level=high` (docs/SECURITY.md 3.4) therefore fails on Astro 5.

Exposure for this project: the SSR-only advisories do not apply to static output. The image-processing ones do: the build will process contributed images (Phase 1 and 2), and a crafted image in a contributor PR runs in CI. Fork PRs run without secrets, which limits the damage, but a build-time RCE is still a supply-chain foothold.

## Options

1. **Astro 7 now** (7.3.x with Vite 8, Zod 4, @astrojs/react 7). Cost is lowest today: only the Phase 0 scaffold exists. Changes: the content config moves to `src/content.config.ts` (Astro 6 removed the legacy location), the Zod mirror uses Zod 4 syntax, Node 22.12 or newer (CI already runs Node 22), and @astrojs/react 7 brings one extra peer package (`oxc-transform-react`).
2. **Stay on Astro 5 with a recorded risk acceptance**: remove sharp through a pnpm override (we do not use Astro's image service), list the remaining Astro advisories in `pnpm.auditConfig` with this ADR as justification, revisit at Phase 2. Cost: an unmaintained major; every new advisory needs a manual triage; the migration grows with every page written.

## Decision

Option 1: upgrade to Astro 7 (7.3.8) before any page, component or island is written, and amend ADR-0001 to read "Astro 7".

## Consequences

- `pnpm audit --audit-level=high` passes again and CI keeps its security gate without exceptions.
- CLAUDE.md, ADR-0001 and docs/ARCHITECTURE.md now say Astro 7 and `src/content.config.ts`; the task files never named a version.
- Codex and Gemini tasks are unaffected in substance: islands are React 19 either way, and themes are CSS.
- Option 2 was not taken, so no advisory is accepted and `pnpm.auditConfig` stays empty.
