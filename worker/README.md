# Worker: static assets + stories API

One Worker serves `dist/` (Astro static output) through the assets binding. `wrangler.jsonc` sets `assets.run_worker_first: true`, so every request reaches the Worker before the binding: it answers `/` and `/api/*` itself, passes everything else to the binding, and adds the security headers to every response it returns (redirects, JSON, assets, 404 pages and 405s alike).

Status: Phase 0. Live routes are `GET /`, `GET /api/health` and the static site. `POST /api/stories` and the daily retention job are planned for Phase 3 and documented below as the contract they will follow; until then every `/api` path other than `/api/health` answers 404.

## Source

| File | What it holds |
|---|---|
| `src/index.ts` | Routing (`export default { fetch } satisfies ExportedHandler<Env>`) |
| `src/security-headers.ts` | `SECURITY_HEADERS`, the one list of headers (docs/SECURITY.md 3.1), and `withSecurityHeaders()` |
| `src/language.ts` | `negotiateLanguage()`, pure, for the `/` redirect |
| `src/health.ts` | `readHealth()`, reads `build.json` |
| `test/*.test.ts` | Vitest, Node environment, with a stand-in for the assets binding |
| `worker-configuration.d.ts` | Generated by `pnpm exec wrangler types worker/worker-configuration.d.ts` (gitignored); rerun after changing `wrangler.jsonc` |

Checks: `pnpm exec tsc -p worker/tsconfig.json`, `pnpm exec vitest run worker/test`, and the Playwright project `edge` (`tests/e2e/edge.spec.ts`, against `wrangler dev` over a fresh `pnpm build`).

## Security headers

`withSecurityHeaders()` sets, replacing any existing value, exactly the headers of docs/SECURITY.md 3.1: `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`. Responses from the assets binding have immutable headers, so the response is rebuilt (`new Response(res.body, res)`) before the headers are set. `test/security-headers.test.ts` compares `SECURITY_HEADERS` with the document: change both together.

## Routes (Phase 0)

### `GET /` and `HEAD /` (edge redirect)

Reads `Accept-Language` and redirects 302 to `/<lang>/` for the supported language (pt, en, es, de, it) with the highest quality, the earliest one on a tie. The primary subtag decides (`pt-BR` picks pt, `de-CH` picks de); ranges with `q=0`, `*` and unsupported or malformed entries are skipped. Fallback `/en/`. Headers: `Vary: Accept-Language`, `Cache-Control: private, max-age=0`. No cookies.

### `GET /api/health` and `HEAD /api/health`

`200 {"ok":true,"build":"<git sha>","date":"<build date, ISO 8601>"}`, `Content-Type: application/json`, `Cache-Control: no-store`. The values come from `build.json`, which the build integration in `astro.config.mjs` writes into `dist/`; the Worker reads it with a GET through the assets binding. When the file is missing or invalid the answer is still `200 {"ok":true,"build":"unknown","date":null}`. Nothing else is ever included: no secrets, no bindings besides `ASSETS`, no DB access. Any other method: `405` with `Allow: GET, HEAD`.

### Everything else under `/api`

`/api` and `/api/...`, any method, `POST /api/stories` included: `404 {"error":"not_found"}` until Phase 3.

### Static site

`GET` and `HEAD` go to the assets binding, which applies `html_handling: "auto-trailing-slash"` and `not_found_handling: "404-page"` (the nearest `404.html`, so `/pt/...` gets the Portuguese page). Any other method: `405` with `Allow: GET, HEAD`.

### Logging

The Worker logs nothing itself: no bodies, headers or IPs (docs/SECURITY.md 3.2). `wrangler.jsonc` keeps Workers Logs on for uncaught exceptions and the Worker's own console output (which is empty), and turns invocation logs off (`observability.logs.invocation_logs: false`, inherited by `env.preview`), so Workers Logs store no request headers, IPs or locations.

## Planned for Phase 3

### `POST /api/stories`

Request: `Content-Type: application/json`, body <= 8 KB:

```json
{
  "exhibit_id": "ab-plc-5",
  "display_name": "Carlos M.",
  "role": "Engenheiro de automação",
  "country": "BR",
  "original_lang": "pt",
  "year_of_memory": 1998,
  "text": "...",
  "contact_email": "optional@example.com",
  "consent": { "publish_with_display_name": true, "license": "CC-BY-4.0", "machine_translation": true },
  "turnstile_token": "...",
  "website": ""
}
```

`website` is a honeypot: any non-empty value is silently accepted with 202 and discarded.

Processing: Zod validation mirroring `content/schema/story.schema.json` (limits identical), Turnstile siteverify with the secret, rate limit (Cloudflare rule + `ip_hash` count per 24 h <= 5), strip HTML tags and control characters, insert with `status = 'pending'`.

Responses: `202 {"id":"st-..."}` on success; `400` on validation or Turnstile failure (generic message, no field hints beyond what the client already validates); `413` on oversized body; `415` on wrong content type; `429` on rate limit. Never echoes stored data.

### Scheduled job (Cron Trigger, daily)

Delete `rejected` rows older than 30 days; null out `ip_hash` older than 30 days. The `triggers` block in `wrangler.jsonc` is commented out until the `scheduled()` handler exists: a cron without a handler only produces errors.

## Bindings (wrangler.jsonc)

- `ASSETS`: static assets (`dist/`), with `run_worker_first: true`.
- `DB`: D1 `plcmuseum-stories` (schema in `schema.sql`). Declared now, read by no route until Phase 3.
- Secrets (`wrangler secret put`, Phase 3): `TURNSTILE_SECRET`, `IP_HASH_SALT` (rotate monthly).
- Vars: `TURNSTILE_SITE_KEY` (public), `ENVIRONMENT`.
- No `compatibility_flags`: the Worker uses no Node APIs.

## Moderation (owner only, local) and publication (deploy only)

`pnpm stories:moderate --list` prints pending stories; `--approve <id,...>` and `--reject <id,...>` update rows in D1 through `wrangler d1 execute` with the owner's credentials. These commands are owner-only: `.claude/settings.json` denies them (and every `wrangler deploy`, `d1`, `secret`, `versions` and `rollback` form, plus `scripts/deploy.mjs`) to Claude Code. Publication: the deploy workflow runs `pnpm stories:fetch`, which reads approved rows (no contact e-mail, no ip hash) into the gitignored `content/stories/` cache for the build. Stories are never committed to the repository (ADR-0008); `stories:fetch` fails without a token (fork and contributor builds never run it), and only development builds fall back to the fictional `src/fixtures/stories.ts`.
